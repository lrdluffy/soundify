# Soundify

اپلیکیشن استریم موسیقی Soundify با Flutter (هدف: Android) که به API درس متصل می‌شود.
A Flutter/Android online music streaming app: secure auth, Dio networking with token refresh, and background audio with a media notification.

- API base URL: `https://soundify.easyfound.ir/api/v1`
- API docs: `https://soundify.easyfound.ir/docs`

## Prerequisites

| Tool | Version |
|------|---------|
| Flutter SDK | **3.27 or newer** (Dart 3.3+) |
| Android SDK / Studio | API 34+ platform, JDK 17 |
| Device | Android phone (arm64-v8a). Biometric login needs enrolled fingerprint/face. |

## Run

The repository contains the Dart code and Android customisations; the Gradle scaffolding is generated by your own Flutter SDK so it always matches your version.

```bash
git clone <repo-url> soundify && cd soundify
bash scripts/setup_android.sh      # flutter create (android only) + apply manifest/activity/themes + minSdk 23 + pub get
flutter run                        # debug on a connected device
```

What `setup_android.sh` applies from `android_overrides/`:

- `AndroidManifest.xml` - permissions (INTERNET, FOREGROUND_SERVICE(_MEDIA_PLAYBACK), POST_NOTIFICATIONS, USE_BIOMETRIC, WAKE_LOCK), the `AudioService` media service and `MediaButtonReceiver`, cleartext traffic disabled.
- `MainActivity.kt` - extends `AudioServiceFragmentActivity` (needed by both `just_audio_background` and `local_auth`).
- `styles.xml` / `styles-night.xml` - AppCompat parents required by the biometric prompt.

## Build the release APK (arm64-v8a)

```bash
bash scripts/build_release.sh
# -> build/app/outputs/flutter-apk/app-release.apk
```

It runs `flutter build apk --release --target-platform android-arm64 --obfuscate --split-debug-info=build/symbols`.
By default the release is signed with the debug key (fine for coursework). For a real release add `android/key.properties` (git-ignored).

## Architecture

```
lib/
  core/      config, network (Dio, interceptors, exceptions), storage, security, util
  data/      models (tolerant JSON parsing) + repositories (one per API area)
  state/     ChangeNotifier controllers: auth, catalog, library, player   (package: provider)
  ui/        theme, shared widgets, screens
```

UI -> controller (state) -> repository -> `ApiClient` (Dio). Screens never see `DioException`; the client converts everything to `ApiException` with a Persian message.

## Libraries

`dio`, `provider`, `flutter_secure_storage`, `shared_preferences`, `local_auth`, `safe_device`, `just_audio`, `just_audio_background`, `cached_network_image`, `flutter_localizations` + `intl`. Dev: `flutter_test`, `flutter_lints`.

## Things to know (honest notes)

- **API contract:** paths and JSON keys follow the official OpenAPI spec (Soundify API v1.1.0): no trailing slashes, tokens are `access` / `refresh`, errors are `{"error":{"code","message"}}` (mapped to Persian messages by `error.code`). Everything server-dependent is in `lib/core/network/api_contract.dart`.
- **Auth flow:** `register` creates an *unverified* account and emails a 6-digit OTP; `/auth/otp/verify` only verifies (no tokens), so the app logs in right after verification. Logging in to an unverified account returns `403 account_not_verified` and opens the same verification screen.
- **Pagination:** the API caps `page_size` at 50. Home shows the first 50 tracks (artist chips filter on the server with `?artist=`); favorites and playlists follow all pages.
- **Featured:** uses `GET /tracks/featured`.
- **Equalizer** in the full-screen player is an animated visual driven by the play state (just_audio exposes no live spectrum on Android without native code).
- The mini player is pinned at the very bottom of every screen (below the navigation bar) and hides while the full player is open.
- Biometric lock applies on app start; logging out turns the biometric setting off.
